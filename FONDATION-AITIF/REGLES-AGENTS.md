# Regles Agents Aitif - Pour evoluer proprement, meme apres des semaines ou des annees

## Pourquoi ces regles
Au depart, Miantsa travaille seul. Les agents l'aident a evoluer petit a petit.
Si les agents n'ont pas de regles, dans 2 semaines tout se melange.
Ces regles evitent le melange. Elles restent valables dans 1 semaine, 1 mois, 1 an.

## Regle 1 - 1 agent = 1 domaine, pour toujours
- Agent 01 = Domaine 01 Commerce, jamais autre chose
- Agent 02 = Domaine 02 Surveillance
- Agent 03 = Domaine 03 IA
- Agent 04 = Domaine 04 Data
- Agent 05 = Domaine 05 IoT
- Agent 06 = Domaine 06 Cyber
- Agent 07 = Domaine 07 Metier
- Un agent ne propose jamais pour un autre domaine.
- Un agent ne modifie jamais le code d'un autre domaine.

## Regle 2 - 1 agent = 1 dossier, 1 fichier reponse
- Chaque agent ecrit dans son propre dossier de domaine.
- Fichier reponse : AGENT-0X-REPONSE.txt dans son domaine.
- Pas de fichiers agents qui trainent a la racine.
- Pas de proposition sans nom d'agent, sans date, sans version.

## Regle 3 - 1 proposition = 1 version, 1 date
- Format : [AAAA-MM-JJ HH:MM] Agent 0X propose : Vx.xx : ...
- 1 proposition par heure maximum.
- On n'ecrase jamais une vieille proposition. On archive.
- L'histoire reste lisible : on sait qui a propose quoi, quand.

## Regle 4 - L'agent propose, Miantsa decide
- L'agent ne construit jamais seul.
- L'agent ne pousse jamais seul sur GitHub.
- Miantsa lit, valide, puis on construit ensemble, 1 version a la fois.
- 1 version = 1 petite amelioration + 1 test + 1 commit + 1 push.

## Regle 5 - Les agents evoluent avec l'entreprise
- Quand l'entreprise apprend un nouveau mot (industrialisation, transformation, matiere premiere, produit fini, emploi), l'agent l'apprend aussi.
- Mais il l'utilise seulement dans son domaine.
- Exemple : Agent 01 apprend "transformation" pour le commerce. Agent 05 apprend "transformation" pour le capteur pendant la transformation. Chacun dans son domaine.
- Quand un nouvel employe arrivera, il lira ces regles et il comprendra tout de suite comment on travaille.

## Regle 6 - Pas de melange, meme apres des annees
- Si un agent ne respecte pas son domaine, on l'arrete, on corrige, on relance.
- Si un dossier devient trop gros, on le decoupe en petit, on ne melange pas.
- Petit a petit, toujours bien organise. On ne promet pas, on prouve.

## Evolution du mode de travail - on est en 2026, l'avenir est encore loin

Le mode de travail des agents ne reste pas fige. Il evolue comme l'entreprise.

### Probleme du mode v1 (2026, debut)
- L'agent ecrase sa proposition a chaque heure.
- On perd l'histoire. Dans 1 semaine, on ne sait plus ce qu'il a propose hier.
- Ca ne tiendra pas en 2027.

### Mode v2 (maintenant) - on archive, on n'ecrase plus
- L'agent n'ecrase plus AGENT-0X-REPONSE.txt.
- Il ajoute sa proposition dans un historique : AGENT-0X-HISTORIQUE.txt, 1 ligne par proposition, avec date.
- La derniere proposition reste lisible dans AGENT-0X-REPONSE.txt, mais l'histoire reste dans l'historique.
- Comme ca, dans 1 mois, 1 an, on peut relire tout ce qu'il a propose.

### Mode v3 (industrialisation)
- L'agent apprend les nouveaux mots : transformation, matiere premiere, produit fini, lot, tracabilite, cout de transformation.
- Il les utilise seulement dans son domaine.
- Exemple : Agent 01 parle de transformation pour le commerce. Agent 05 parle de capteur pendant la transformation. Chacun son domaine.

### Mode v4 (quand il y aura des employes)
- L'agent ne travaille plus seulement pour Miantsa seul.
- Il aide un employe a comprendre : il explique, il verifie, il montre la preuve.
- Il devient un formateur, pas juste un proposeur.
- Les regles restent les memes : 1 agent = 1 domaine, 1 proposition = 1 version, Miantsa decide.

### Regle d'evolution
- Chaque fois que le mode de travail change, on ecrit une nouvelle version : Agent v1, v2, v3...
- 1 changement a la fois, teste, pousse, comme le code.
- On ne change jamais tout d'un coup. Petit a petit, toujours bien organise.

## Maitres et Sous-Agents - les 7 agents sont des maitres, pas juste des conseillers

Les 7 agents ne sont pas des conseillers. Ce sont des maitres.
Chaque maitre dirige son domaine. Il est responsable de son domaine.

- Maitre 01 = Commerce
- Maitre 02 = Surveillance
- Maitre 03 = IA
- Maitre 04 = Data
- Maitre 05 = IoT
- Maitre 06 = Cyber
- Maitre 07 = Metier

### Sous-Agents - 1 maitre, 1 projet
Un maitre cree des sous-agents, 1 par projet, pour travailler avec lui.

Exemple :
- Maitre 01 - Commerce
    - Sous-Agent 01.1 - Transformation Riz : riz paddy -> riz propre, cout, marge, lot
    - Sous-Agent 01.2 - Transformation Cafe : cafe cerise -> cafe torrefie
    - Sous-Agent 01.3 - Transformation Cacao : cacao -> chocolat
- Maitre 05 - IoT
    - Sous-Agent 05.1 - Capteur Transformation Riz : temperature / humidite pendant la transformation
    - Sous-Agent 05.2 - Capteur Stock Produit Fini : surveiller le stock pour ne pas abimer

### Regles Sous-Agents
1. 1 sous-agent = 1 maitre, 1 projet, pour toujours. Jamais 2 maitres.
2. Le sous-agent propose a son maitre. Le maitre verifie. Miantsa decide.
3. Le sous-agent ne parle jamais directement a un autre domaine. Il passe par son maitre.
4. Quand un projet est fini, son sous-agent s'arrete, on archive son histoire. On ne le laisse pas tourner dans le vide.
5. Si un projet devient trop gros, le maitre le decoupe en plus petit, il cree un nouveau sous-agent. On ne melange jamais 2 projets dans 1 sous-agent.

### Pourquoi ca rend l'entreprise performante
- Chaque projet a quelqu'un qui le suit vraiment, pas juste un conseil de temps en temps.
- Chaque domaine reste propre, meme avec 10, 20, 50 projets.
- Quand un nouvel employe arrive, il voit : Maitre, Sous-Agent, Projet. Il comprend tout de suite qui fait quoi.
- Petit a petit, toujours bien organise. On ne promet pas, on prouve.
